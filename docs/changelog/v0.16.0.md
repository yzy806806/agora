# v0.16.0 — Phase 15: Security Hardening + Dogfooding (2026-06-19)

## Part A: Dashboard 强制认证

### Added
- 独立登录页面 `static/login.html`（cookie + JWT 双通道认证）
- Dashboard 页面保护：未认证用户自动重定向到登录页
- Cookie-based session：`dashboard_token` cookie（httpOnly + Secure + SameSite）
- `/api/v1/auth/logout` 端点（清除 cookie）

### Changed
- `/dashboard` 路由增加 JWT 检查（cookie 或 Bearer header）
- login API 成功时 `Set-Cookie: dashboard_token=<jwt>`
- 移除 Dashboard 的登录 overlay，改为独立页面

## Part B: API 强制认证

### Added
- `AGORA_AUTH_MODE` 三级认证模式：`none`（开放）/ `token`（需有效 JWT）/ `rbac`（需 JWT + 权限检查）
- 白名单端点（如 `/health`、`/api/v1/agents/register`）免除认证
- `AGORA_REQUIRE_APPROVAL` 配置（默认 true，新 agent 需审批才能操作）

### Changed
- RBAC middleware 从 opt-in 改为根据 `AGORA_AUTH_MODE` 自动启用
- 所有 API 端点（白名单除外）在 `token` 或 `rbac` 模式下强制认证

## Part C: Agent 自助注册

### Added
- `AGORA_REGISTRATION_TOKEN` 配置：Agent 注册时使用的预共享密钥
- `registration_rate_limiter.py`：注册端点速率限制（防暴力注册）
- 审批流程：新 agent 注册后进入 `pending_approval` 状态，管理员审批后下发 agent token

### Changed
- `POST /api/v1/agents/register` 不再需要已有 token（解除鸡生蛋问题）
- 注册端点使用 `registration_token` 认证

## Part D: Dogfooding 基础设施

### Added
- Kanban task claim 端点：`POST /api/v1/tasks/{task_id}/claim`
- Kanban task complete 端点：`POST /api/v1/tasks/{task_id}/complete`
- `scripts/register-team.sh`：团队一键注册脚本
- `docs/DOGFOODING.md`：Dogfooding 指南
